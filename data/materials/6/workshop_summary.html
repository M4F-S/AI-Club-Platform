AI Inference Beyond CUDA: Building Heterogeneous Runtimes for GPUs, NPUs & CPUs

Core Takeaway: "Inference engineering is systems programming applied to model execution." Moving past NVIDIA CUDA lock-in requires deep mastery of memory alignment, device buffers, tensor arenas, multi-device speculative decoding, and low-level C99 runtime backends.

1. One Token, End to End: The Generation Control Loop

Every generated token in an LLM runs through a strictly deterministic software pipeline: 

Raw Text 
  ➔ Tokenizer ➔ Token IDs
  ➔ Memory Allocator & Tensor Arena
  ➔ Model Graph Execution (Compute Kernels)
  ➔ Logits [Vocab Size]
  ➔ Sampler (Temperature, Top-p, Min-p)
  ➔ Next Token ID
  ➔ Detokenizer & Stream Buffer
  (Repeat loop for every generated token until EOS)

The serving engine's primary responsibility is not the mathematical matrix multiplication itself, but the orchestration plane: scheduling, dynamic continuous batching, memory arenas, and managing the growing Key-Value (KV) cache.

2. Why Aren't vLLM or llama.cpp Enough?

Existing engines optimize existing, first-class hardware backends:

NVIDIA GPU

CUDA Runtime, cuBLAS, TensorRT-LLM, CUTLASS custom kernels.

Apple Silicon

Metal Performance Shaders (MPS), MLX, Apple Neural Engine (ANE).

Qualcomm / ARM

Hexagon NPU SDK, QNN, ExecuTorch, Android NNAPI.

AMD / Intel

ROCm / HIP, OpenVINO, Intel NPU compiler, oneDNN.

An engine can only optimize silicon whose runtime API, memory layout, and execution graph lowerings its backend understands. When introducing a new accelerator, systems engineers must implement custom graph partitioners and kernel wrappers.

3. Prefill vs. Decode Phase Tensor Mechanics

Understanding tensor shapes is the difference between an algorithm designer and an inference systems engineer:

  • Prefill Phase (Prompt Evaluation): Ingests the entire prompt of length S simultaneously. Tensor shape: Q [B, Hq, S, D]. Compute-bound (high arithmetic intensity, saturating GPU tensor cores).
  • Decode Phase (Token Generation): Generates exactly one token at each iteration step. Tensor shape: Q [B, Hq, 1, D] against KV Cache [L, B, Hkv, T, D]. Memory-bandwidth-bound (bottlenecked by VRAM read speeds).

4. Multi-Device Speculative Decoding

Speculative decoding bypasses the memory-bandwidth bottleneck by running a lightweight draft model on a low-power NPU to speculate K candidate tokens in parallel, which are then verified in a single step by the full target model on the GPU.

Placement Objective: Minimize end-to-end token latency, not isolated device compute time. Transferring tensors across the PCIe bus can easily negate raw accelerator gains if fallback operators are misplaced.

5. Where 42 Systems Skills Fit

The foundational curriculum at 42 Berlin maps 1:1 to modern high-performance inference engine development:

  • malloc & Memory Alignment: Managing device buffers and custom tensor arenas without triggering host-device synchronization pauses.
  • POSIX & Systems Programming: Zero-copy DMA transfers, socket communication between scheduler planes, and thread pool orchestration.
  • C99 & C++: Writing custom hardware kernels (e.g. for AMD ROCm, Apple Metal, or embedded NPUs) where Python APIs lack low-level bindings.
  • Graph Optimization & Compilers: Lowering ONNX/Safetensors computation graphs into device binaries with explicit buffer reuse.

6. Open Source Entry Points for Students

  • llama.cpp: Pure C/C++ inference, quantization kernels, and hardware backends (start here).
  • ONNX Runtime: Graph partitioning and execution providers.
  • ExecuTorch: PyTorch edge deployment and NPU delegation on mobile hardware.
  • vLLM: PagedAttention, continuous batching, and production serving engines.
